# 工作日誌系統 (Cyber Worklog System)

基於 Python + CustomTkinter 的桌面工作日誌管理工具，支援案件登錄、轉交紀錄整理與複製、資料庫搜尋與設定同步。

## 功能總覽

- **總覽**：每月件數統計（總件數 / 已處理 / 待處理 / 轉交），點擊統計卡可帶出對應狀態的紀錄；另有各專案件數排行、每日件數分布、本月 vs 上月比較等數據。
- **工作紀錄（主頁）**：登錄案件（專案 / 學校 / 聯絡人 / 電話分機 / 問題內容 / 處理情形 / 個資），狀態分為「已處理 / 待處理 / 轉交」，登錄時自動記錄開始與完成時間；可一鍵開啟專案網頁、匯出當月 Excel 報表、批次刪除與編輯，歷史紀錄可依狀態篩選。
- **轉交系統**：依年 / 月篩選狀態為「轉交」的案件，顯示格式與歷史紀錄一致；逐筆或一次複製整理好的工作日誌文字，自行貼到 LINE 或其他通訊軟體發送。
- **資料庫搜尋**：列出 SQLite 內所有資料表（含 `sqlite_` 開頭的系統資料表）與欄位，點資料表自動帶入 SQL，直接執行查詢並以表格呈現結果。
- **基本資料設定**：專案 / 學校 / 人員管理（新增、編輯、移除、手動排序、每頁 20 筆分頁）；學校採**全庫唯一**設計，可快速把既有學校加入其他專案，重複輸入時會提示是否直接加入目前專案；設定資料可匯出成 JSON 檔並在另一台電腦做差異比對匯入。
- **暗色主題介面**、狀態時間自動記錄、案件狀態一鍵切換。
- **主題系統**：側邊欄底部「🎨 主題」可切換內建主題（賽博龐克預設、Bocchi 粉紅暗色／粉嫩明亮），可放角色圖片裝飾（側邊欄角色圖、輸入表單角落小圖），選擇會自動儲存、下次啟動沿用；也能自行新增其他角色主題。

## 執行環境

- Windows 10/11
- Python 3.10+（本專案以 Python 3.14 開發驗證）

## 安裝與執行

```powershell
# 1. 建立虛擬環境並安裝相依套件
python -m venv venv
venv\Scripts\pip install -r requirements.txt

# 2. 初始化資料庫（自動建立 worklog.db，含舊版資料庫遷移）
venv\Scripts\python src\main.py

# 3. 啟動程式
venv\Scripts\python src\main.py
```

> 想用範例資料重跑：`venv\Scripts\python reset_db.py`（會刪除並重建 worklog.db，注入測試專案與學校）。

> 嫌指令麻煩？新使用者直接執行 `安裝.bat`（自動建 venv + 裝套件），之後用 `啟動.bat` 一鍵開啟。

## 發布與自動更新（GitHub）

程式內建自動更新：**每次啟動時背景檢查**，也可在「系統設定 → 匯入/匯出 → 程式更新」手動按「🔄 檢查更新」。有新版本時會自動下載、關閉並重新啟動，**你的資料（worklog.db、設定、主題圖）不會遺失**。

### 首次發布（建立 GitHub repo 並上傳）

1. 安裝 git（https://git-scm.com/download/win），並在專案資料夾開終端機。
2. 登入 GitHub（用你的 Google 帳號）：`gh auth login`（沒有 gh 就先 `winget install --id GitHub.cli -e`）。
3. 建立**公開** repo 並上傳目前程式碼：

   ```
   gh repo create worklog-system --public --source . --remote origin --push
   ```

4. 告訴我你的 GitHub 帳號名稱，我會把 `src/core/updater.py` 開頭的 `GITHUB_OWNER` 填上。
5. 打第一個版本標籤：

   ```
   git tag v1.0.0
   git push origin v1.0.0
   ```

   GitHub 會自動產生 `v1.0.0` 的原始碼 zip，所有人的程式即可檢查到更新。

### 之後每次改版

```
改完程式 → 修改 VERSION 檔（例如改成 1.1.0）
python build_release.py          # 產生發布 zip 並印出步驟
git add -A
git commit -m "v1.1.0"
git push
git tag v1.1.0
git push origin v1.1.0
```

其他人下次開啟程式就會收到更新通知，一鍵更新並自動重啟。

### 資料安全

- `worklog.db`、`config/`（設定與自訂主題）已在 `.gitignore` 排除，**永遠不會上傳到 GitHub**。
- 更新時只「新增/覆蓋」程式檔，`worklog.db`、`config/`、`assets/themes/custom_*` 一律保留。

## 頁面說明

### 總覽（Overview）

- 依年 / 月顯示「總件數 / 已處理 / 待處理 / 轉交」統計卡，切換年月即更新。
- 點擊統計卡會在下方帶出對應狀態的紀錄清單（點「總件數」= 全部），作用中的卡會高亮。
- 右側數據面板：各專案件數排行（進度條＋百分比）、每日件數分布（標出高峰日）、本月 vs 上月比較（各狀態增減）。

### 工作紀錄（Dashboard）

- 登錄表單：選擇專案 / 學校 / 聯絡人，輸入電話分機、問題內容、處理情形與個資；按下「已處理 / 待處理 / 轉交」切換狀態，選「轉交」時可指定轉交人員。
- 歷史紀錄：以卡片顯示每月紀錄（時間 | 專案 | 學校 | 問題內容 | 電話 | 聯絡人 | 狀態；下方為處理情形、個資、轉交人員），可依狀態篩選（全部 / 已處理 / 待處理 / 轉交）、勾選批次刪除或進入編輯。
- 📊 匯出當月報表：匯出為 Excel（欄位：序號、星期、日期、時間、專案、學校、問題內容、處理情形、完成日期、完成時間、案號），個資欄位不匯出。

### 轉交系統（Transfer）

- 依年 / 月篩選「轉交」狀態的紀錄，卡片顯示與歷史紀錄相同。
- 每張卡片有「📋 整理並複製」按鈕；頁首有「📋 複製全部」可一次整理整月紀錄。
- 點擊後會先顯示整理好的工作日誌文字（日期、專案、學校/單位、問題內容、電話、聯絡人、處理情形、個資、轉交對象），按下「複製到剪貼簿」即可貼到任何地方手動轉交。

### 資料庫搜尋（DB Search）

- 左側列出資料庫中**所有**資料表與其欄位（含 SQLite 系統資料表如 `sqlite_sequence`），點資料表自動帶入 `SELECT * FROM "資料表" LIMIT 100;`。
- 右側可直接輸入 SQL（支援 SELECT / INSERT / UPDATE / DELETE，修改類語句執行後自動存檔），按 F5 或「執行」查詢，結果以表格呈現，最多顯示前 200 列。

### 系統設定（Settings）

- 專案管理：新增 / 編輯 / 刪除專案與網址，可手動排序；刪除專案會一併解除學校關聯（學校本身保留）。
- 學校管理：學校在全庫**只會存一間**，透過專案關聯分派；依專案檢視學校（含學校代碼）可手動排序；新增學校若在全庫已存在，會提示「已存在，是否加入目前專案？」；按「＋ 從現有學校加入此專案」會切換成**快速加入模式**，列出未加入此專案的全庫學校（可依名稱/代碼搜尋、勾選單筆或多筆一次加入），加入完成後自動回到原本的專案學校清單；每列可編輯（全域改名/代碼）或移除（解除關聯，不刪除學校）。
- 人員管理：新增 / 編輯 / 刪除轉交人員，可手動排序、依名稱排序、分頁顯示。
- 匯入 / 匯出：將專案、全庫學校、專案學校關聯、轉交人員匯出成 JSON 檔（格式 v2）分享給其他電腦；匯入時先做差異比對（新增 / 衝突 / 相同），再依選擇套用；可讀取舊版 v1 匯出檔並自動轉換。

## 主題系統（Theme）

- **切換方式**：側邊欄最下方的「🎨 主題」按鈕，會開啟主題選擇視窗（含色票預覽與明暗標示），點「使用」立即套用並儲存，重開程式後沿用。
- **內建主題**：
  - `cyber`　賽博龐克（預設，即原本的暗色風格）
  - `bocchi-dark`　孤獨搖滾・後藤一里（Bocchi）粉紅暗色
  - `bocchi-light`　孤獨搖滾・後藤一里（Bocchi）粉嫩明亮
- **切換行為**：套用主題會重建整個介面，未存檔的表單輸入會被清空（目前所在頁面會保留）。
- **設定檔**：目前使用的主題與隱藏清單存在 `config/settings.json`（`{"theme": "cyber", "hidden_themes": []}`），自訂主題則存於 `config/themes.json`，皆由 `src/ui/theme_registry.py` 統一讀寫。
- **色票設計**：所有介面顏色皆對應語意 token（`BG_DARK`、`NEON_CYAN`、`STATUS_PENDING` 等），不會因為切主題而出現「漏改」的顏色。全專案透過 `src/ui/theme.py` 的動態代理讀取目前主題，視圖程式碼不需逐一改色。

### 角色圖裝飾（需要圖片才顯示）

把圖檔放進 `assets/themes/<主題名稱>/` 即可自動套用，檔案不存在時該圖會自動隱藏、程式不會出錯：

| 檔名 | 位置 | 建議規格 |
| --- | --- | --- |
| `mascot.png` | 側邊欄底部、主題按鈕上方 | 透明背景 PNG，約 250×250 |
| `input.png` | 工作紀錄輸入表單右上角（「趴在上面」效果） | 透明背景 PNG，約 72×92 |

> 注意：圖片請使用你自行擁有的素材（勿使用有版權的官方圖片）。

### 自製角色主題（例如灰原哀、初音未來…）

現在不需要寫程式，直接透過介面即可完成：

1. 在「🎨 主題」選擇視窗按「➕ 新增主題」。
2. 輸入**主題名稱**、選擇**明暗**（🌙 暗色 / ☀️ 明亮）。
3. 點各色票按鈕開啟 **Windows 原生色彩選擇器**挑色（共 14 個語意色票，分背景／強調／狀態三組），或按「🎀 套用預設配色」填入粉嫩預設再微調。
4. 按「建立主題」→ 自動建立 `assets/themes/custom_N/` 資料夾並**立即套用**。
5. 把角色圖放進該資料夾（`mascot.png`、`input.png`，見上表）即可看到裝飾。

**刪除與隱藏**：主題選擇視窗中，自訂主題有「🗑️ 刪除」按鈕（可選擇是否連圖片資料夾一起刪除，預設保留）；任何主題（含內建）都有「🙈 隱藏／👁 顯示」按鈕，隱藏後不會再出現在清單中。

## 資料表

| 資料表 | 說明 |
| --- | --- |
| `worklogs` | 案件記錄（專案 / 學校 / 聯絡人 / 內容 / 狀態 / 轉交對象 / 時間等） |
| `projects` | 專案（名稱、網址） |
| `schools` | 學校（**全庫唯一**，含學校代碼，不含專案欄位） |
| `project_schools` | 專案 ↔ 學校多對多關聯（含排序，`ON DELETE CASCADE`） |
| `contacts` | 轉交人員（姓名、電話分機） |
| `sqlite_sequence` | SQLite 系統資料表（AUTOINCREMENT 計數） |

## 開發者備註

- 舊版資料庫（`schools` 帶 `project_id`、每個專案重複存學校）會在 `init_db()` 啟動時自動遷移：依 `school_name + school_code` 去重合併、重映射 `worklogs.school_id`、回填 `project_schools`、重建 `schools` 表移除 `project_id`。以本專案實際資料為例，遷移後學校 204 筆 → 185 間、關聯 204 筆。
- 登入頁的案件下拉框（Enter 過濾）刻意不使用原生彈出選單：Windows 下原生選單會鎖住鍵盤，導致 Enter 後無法用 Backspace 刪字，故改為只過濾、由右側箭頭下拉選取。
- 新增視圖時，於 `main_window.py` 的 `_build_sidebar()` / `show_view()` 註冊按鈕與頁面即可。
